# 输入契约

本页描述软件接口，不代表所有设备已经取得物理输入。

| 功能 | 当前实现 |
| --- | --- |
| 点击、拖动、长按 | 鼠标左键或 CE 标准触摸消息；按实际画面区域映射，黑边不触发点击 |
| 双指 | 共享核心发送两个稳定联系人；Windows 原生 WM_TOUCH，CE 专有驱动可用下列事件入口 |
| 控制器 | 方向键导航、滚轮旋钮、Enter 确认、Home 首页、Backspace 返回 |
| 媒体 | 播放、暂停、播放/暂停、上一首、下一首；支持媒体键和 Windows WM_APPCOMMAND |
| 电话和 Siri | F6 接听、F7 挂断、F8 按下/松开 Siri；手机决定实际通话与识别状态 |
| 昼夜和画面恢复 | F9 切换昼夜、F5 请求关键帧；昼夜状态跨自动重连保留 |
| 麦克风上行 | 手机请求后通过系统 waveIn 采集 PCM，经共享核心加密发回；流结束立即释放 |
| 返回车机界面 | 处理手机 requestUI，最小化接收端；modesChanged 记录到 host-events.plist |
| 输入生命周期 | 失焦/捕获丢失释放按键和联系人；合并移动事件，队列溢出释放而非留下卡住的按下状态 |

空格控制播放/暂停，Windows 原有 F11 全屏不变。不需要为“点击”和“长按”做两条协议：持续按下、移动、松开的 HID 报文由手机解释。触摸与按键在事件通道建立后才发送，不重放断线期间的操作。鼠标和触摸共用 `core/input.*`，窗口转换位于 `platform/common/window_input.h`，两平台不维护两份协议实现。

车机适配程序可以向 WinXPlay 顶层窗口发送 `platform/common/input_messages.h` 定义的消息。参数均为整数，无跨进程指针：

| 消息 | wParam | lParam |
| --- | --- | --- |
| `WM_APP+20` CONTACT | 位0为联系人槽0/1，位8为按下状态 | 低16位 X、高16位 Y，按画面归一化到0..65535 |
| `WM_APP+21` KEY | InputKey 编号 | 1按下、0松开 |
| `WM_APP+22` NAVIGATE | 有符号旋钮步数 | 低/高16位为有符号 X/Y 导航轴 |
| `WM_APP+23` NIGHT | 1夜间、0白天 | 0 |
| `WM_APP+24` CANCEL | 0 | 0 |
| `WM_APP+25` KEYFRAME | 0 | 0 |
| `WM_APP+26` VISIBLE | 1恢复前台、0最小化 | 0 |

InputKey 固定编号：0确认、1首页、2返回、3播放、4暂停、5播放/暂停、6下一首、7上一首、8接听、9挂断、10 Siri。驱动丢失输入、倒车接管或停止转发时应发送 CANCEL。标准 WM_MOUSE/WM_KEY 消息也能直接工作；这些入口不凭空产生尚未解决的触屏、CAN 或方向盘驱动事件。VISIBLE 只管理接收端窗口，不能代表已经完成原厂显示层/音源交接。


能力与实测边界见 [兼容性表](../../docs/compatibility.md)。
