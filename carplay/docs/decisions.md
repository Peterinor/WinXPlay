# 当前技术决策

| 决策 | 原因与约束 |
| --- | --- |
| 共享核心、平台实现、薄设备适配 | 协议只维护一份，车型差异有明确归属 |
| 核心及公共契约保持 C++03 | 兼容当前 CE 工具链；现代 SDK 仅进入 Windows 私有实现 |
| 优先系统媒体 API | 复用已有解码和输出组件，不要求各平台采用同一种 API |
| Windows 使用 MF/D3D11 | 保持系统媒体路径，FFmpeg 仅用于开发素材 |
| MRN 选择 CE DirectShow 内存源 | 平台实现持续 H.264 输入和图管理，设备配置选择滤镜；Generic 不默认启用 |
| CE 提供 PCM/wave，设备决定输出策略 | 未实现的 AAC 不声明；MRN 的 TTS 路由及音频恢复属于设备实现 |
| 完整 VideoPipeline 边界 | 避免要求所有后端读回 RGB，原生表面留在平台内部 |
| 静态组合和少量配置 | 当前没有运行时插件的实际需求 |
| HMI 桥接位于独立设备模块 | 原厂进程处理图层和输入，主程序只接收标准窗口消息 |
| 真实身份外置 | 合成测试与真实配件认证分开，源码不包含私钥 |
| 产品根目录独立 | 构建、测试、文档不隐式引用上层研究区 |

历史方案、迁移推导与失败尝试保留在研究工作区。重新评估以上决定应给出真实平台需求、性能测量或回归结果，并同时更新当前架构与验证边界。
