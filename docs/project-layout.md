# 项目结构与研究边界

本目录包含构建、使用、测试和维护 WinXPlay 所需的自有源码与说明。上层研究工作区用于保留原厂材料、探索脚本、完整实验时间线和原始证据，不作为公开项目的隐式依赖。

| 内容 | 所属位置 |
| --- | --- |
| CarPlay 协议、会话、媒体组帧与输入消息 | carplay/core、interfaces |
| Windows/WinCE 系统 API、窗口、网络与媒体机制 | carplay/platform |
| 设备参数、原车音源和 USB 兼容实现 | carplay/devices |
| HMI 桥接、固件补丁生成代码 | firmware/对应设备 |
| 通用工具及其配置示例 | tools/对应工具 |
| MRN 专属 AV、连接、输入诊断 | carplay/tools/mrn |
| 多模块共享的诊断源码 | common |
| 工具链、部署包生成、依赖检查 | scripts |
| 跨模块契约和编译后 ARM 测试 | tests |
| 接收端自身测试和合成对端 | carplay/tests |
| 安装、移植约束和验证结论 | docs |
| 可重新生成的文件 | build，忽略版本控制 |
| 原厂二进制、完整抓包、研究过程 | 本项目以外的研究工作区 |

设备边界以依赖的契约判断：wave/DirectShow、窗口消息与 USB 主机 API 属于平台机制；指定滤镜、音源通道、固件兼容和原厂界面接管属于设备策略。

设备特有代码不是研究废料。已采用的 MRN 适配保留在项目内，但不得把固件地址、音源选择和 OEM 窗口名散布进共享协议核心。

支撑这些实现的设备接口结论同样保留在源码文档中，见 [MRN 设备说明](devices/mrn.md)：记录原厂行为、采用原因、对应代码及验证边界。移出的是研究过程和批次日志，不是实现所需的依据。

脚本从自身位置定位项目根目录，不依赖启动时的工作目录名称。原厂文件等不可分发输入通过明确的环境变量指定，不能默认寻找父目录的 evidence/research。产品测试如需要这类输入，必须写明依赖和验证范围。

历史 build 交付包属于证据，不搬进新的 build 冒充重建结果。新的 build 可以在退出相关程序后清理重建；默认打包只写本地目录，不部署到车机。

源码整理、迁移和环境审查的执行记录保留在本项目以外；产品文档只维护构建要求、使用方法、架构约束和适用范围等可复用结论。
